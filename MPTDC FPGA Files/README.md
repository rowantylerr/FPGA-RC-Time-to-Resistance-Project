# Multi-Phase TDC (MPTDC) FPGA Implementation

**Author:** Rowan Tyler

---

## Introduction

This folder contains the most precise FPGA implementation of the RC-circuit TDC. It uses a Multi-Phase Time-to-Digital Converter (MPTDC) architecture to achieve approximately 800 MHz effective time resolution from a 200 MHz PLL clock. Four independent 200 MHz clocks are generated at 0°, 90°, 180°, and 270° phase offsets; a separate `input_timer` instance runs on each phase. Because the four clocks sample `step_input` at different points within each 5 ns clock period, the edge of `step_input` is captured with approximately 1.25 ns resolution (1 / 800 MHz). The final counter value is the **sum** of all four individual counters.

This design inherits all improvements from the 200 MHz variant (transient guard, minimum discharge time, input synchronisation) and adds multi-clock-domain synchronisation for the `stopped` flags so that counter values are only read once all four timers have definitively halted.

## Module Overview

| File               | Description                                                                               |
|--------------------|-------------------------------------------------------------------------------------------|
| `top.v`            | Top-level module. Instantiates 4 timers and synchronises their `stopped` flags.           |
| `input_timer.v`    | Counter that also exposes a `stopped` output flag for cross-domain synchronisation.       |
| `discharge_timer.v`| Identical to 200 MHz variant: enforces 10 ms minimum discharge time.                     |
| `MPTDC_200.v`      | **Wizard-generated.** Altera `altpll`: produces 4 × 200 MHz clocks at 0/90/180/270°.     |
| `uart.v`           | UART wrapper clocked at 50 MHz (board clock).                                             |
| `baud_rate_gen.v`  | Divides 50 MHz clock to produce 115200 baud TX clock enable.                             |
| `transmitter.v`    | UART transmitter FSM — serialises one byte at a time.                                     |

> **Third-party code:** `baud_rate_gen.v`, `transmitter.v`, and `uart.v` are taken or adapted from the open-source UART-for-FPGA repository by Jamie Iles:  
> [https://github.com/jamieiles/uart](https://github.com/jamieiles/uart)  
> The MPTDC UART subsystem uses the 50 MHz board clock (same constants as the 50 MHz design). See individual file headers for details.

> **`MPTDC_200.v` is auto-generated** by the Quartus MegaWizard and should not be manually edited. To regenerate, use Tools → IP Catalog → ALTPLL in Quartus Prime and configure four output clocks at 90° increments.

## MPTDC Architecture

```
                  Board Clock (50 MHz)
                         │
                         ▼
                  ┌────────────┐
                  │ MPTDC_200  │  (PLL × 4)
                  │  altpll    │
                  └─┬──┬──┬──┬┘
                    │  │  │  │
                  0° 90° 180° 270°  (each at 200 MHz)
                    │  │  │  │
              ┌─────┘  │  │  └─────┐
              │    ┌───┘  └────┐   │
              ▼    ▼           ▼   ▼
           timer_0  timer_90  timer_180  timer_270
              │       │          │         │
              └───────┴──────────┴─────────┘
                           │
                       SUM of all 4 counters
                           │
                    calc_resistance (32-bit)
                           │
                        UART TX
```

Each timer independently detects the rising edge of `step_input` on its own clock phase, freezes its counter, and asserts a `stopped` flag. The main state machine (running on the 0° clock) waits until all four `stopped` flags are synchronised into its clock domain before reading the counter values.

## Installation

1. Install **Intel Quartus Prime Lite** (targets the MAX 10 device family).
2. Create a new Quartus project, add all `.v` files from this folder, and set `top.v` as the top-level entity.
3. Assign pin locations in the Pin Planner:
   - `clk` → 50 MHz oscillator pin
   - `reset_in` → GPIO connected to Raspberry Pi GPIO 24
   - `enable` → GPIO connected to Raspberry Pi GPIO 23
   - `step_input` → GPIO connected to RC circuit output
   - `step_set` → GPIO connected to RC circuit input
   - `uart_tx` → GPIO connected to Raspberry Pi UART RX (GPIO 15)
4. Compile and program via JTAG (Tools → Programmer).

> **Important:** The four phase-shifted clocks are internal signals generated by the PLL. Quartus will automatically route them to the clock network. Do not assign the internal `clk_200_0/90/180/270` wires to I/O pins.

## How to Run

Identical to the 50 MHz and 200 MHz implementations. Use the scripts in `Raspberry Pi Files/` to drive the measurement cycle. See the top-level `README.md` and `Raspberry Pi Files/README.md` for the full procedure.

> **Note on output values:** Because the transmitted value is the **sum** of four counters, the raw FPGA output is approximately four times larger than the equivalent 200 MHz single-phase count. The calibration scripts in `Calibration Files/` account for this automatically when the correct input data is used.

## Technical Details

### PLL Phase Configuration (MPTDC_200.v)

| Output | Phase Shift | Phase Shift (ps at 200 MHz) |
|--------|-------------|------------------------------|
| c0     | 0°          | 0 ps                         |
| c1     | 90°         | 1250 ps                      |
| c2     | 180°        | 2500 ps                      |
| c3     | 270°        | 3750 ps                      |

### Cross-Domain Synchronisation

The `stopped` signals from the 90°, 180°, and 270° timers are generated on their respective clock domains and must be safely transferred to the 0° clock domain before being read. A 2-FF synchroniser is used for each, which is safe here because the `stopped` flag is a static level signal (it goes high and stays high until cleared), so there is no risk of missing a short pulse.

### Effective Resolution

The four timers together capture the `step_input` edge to within one 0°-clock cycle on at least one phase. The phase with the most counts (i.e., the one whose edge was closest to `step_input`) contributes the extra count. Summing all four gives a result equivalent to a single counter running at ~800 MHz with 1.25 ns resolution.

## Known Issues / Future Improvements

- Only the phase-0 `overflow` flag is monitored. In practice all four counters overflow simultaneously, so this is safe, but a more rigorous implementation would check all four.
- Debug output ports (`dbg_counter_200`, `dbg_counter`, `dbg_pll_locked`, `test`) should be removed for a production build.
- The `enable` input is synchronised to the 200 MHz domain in this design (unlike the 50 MHz and 200 MHz variants where it is used directly). This is the correct approach and should be back-ported to the other designs.
- The MPTDC implementation is not able to obtain accuracies comparable to the 200 MHz and 50 MHz implementations. There is likely a bug in the code that has not been found and resolved.
